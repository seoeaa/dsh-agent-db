# dsh-agent-db

[English](README.md) | **Русский**

Временные PostgreSQL-совместимые базы для агентов и субагентов **DeepSeek Harness**.
Агент создаёт свою базу, сохраняет ключевые слова, факты и таблицы, выполняет SQL,
экспортирует результат в JSON/CSV и удаляет базу после работы.

Движок — [PGX](https://github.com/pgrundev/pgx), написанный на Rust.
Этот плагин — адаптер на JavaScript ESM с восемью native tools Harness.
PGX устанавливается отдельно и в пакет не включён.

**Статус: ранняя версия 0.1.0.** Проверено на Linux, Node.js 25.2.1,
Harness **0.2.1-alpha.3**, Cordis **4.0.5-alpha.2**, PGX **0.1.0-beta.1**.
Минимальная версия Node.js для пакета — 24. Другие версии Harness и другие ОС
не проверены. PGX beta предназначен для временных данных: ценные результаты экспортируйте.

## Установка

### 1. Подготовить отдельный PGX

Установите CLI по [официальной инструкции PGX](https://pgx.dev/).
Создайте **отдельный** runtime для этого плагина. Не используйте общий сервер с
важными базами: при запуске адаптер закрывает публичный CONNECT к служебным базам.

```sh
install -d -m 700 "$HOME/.local/state/dsh-agent-db"
export PGX_HOME="$HOME/.local/state/dsh-agent-db/pgx"
pgx init --port 55439
pgx start
pgx doctor
```

Порт 55439 должен быть свободен. Оставьте прослушивание только loopback.
Настройки подключения адаптер читает из `$PGX_HOME/config.json`; пароль агентам
не возвращается. CLI PGX beta.1 требует штатный `trust` для Unix socket;
закрывайте доступ каталогом 0700, TCP может использовать SCRAM.
Для постоянного запуска PGX можно настроить пользовательскую службу systemd.

### 2. Получить и подготовить плагин

Harness должен быть установлен в совместимой версии.

```sh
git clone --branch v0.1.0 https://github.com/seoeaa/dsh-agent-db.git
cd dsh-agent-db
npm ci --ignore-scripts --omit=optional
npm run setup:runtime -- "$(npm root -g)/@deepseek-ai/dsh"
npm run check
```

`setup:runtime` связывает Cordis и dsh-tools с пакетами установленного Harness.
Это сохраняет общий экземпляр runtime. Если Harness установлен другим способом,
передайте фактический каталог его пакета. Скрипт проверяет версии и не заменяет
уже существующие несовпадающие пакеты. После переноса Harness или смены его
Node.js-каталога проверьте ссылки повторно.

### 3. Подключить bundle и инструменты

Из каталога плагина установите пакет в нужный профиль:

```sh
dsh plugin --profile web add "link:$(pwd)"
```

В менеджере плагинов Harness включите bundle `@local/dsh-agent-db`.
Он добавляет Host-сервис `agentDb`. Затем в `config.plugins` выбранного пресета
добавьте строку инструмента, сохранив остальные записи:

```yaml
- id: tool-agent-db
  name: '@local/dsh-agent-db/tools'
```

Для собственных путей задайте параметры сервису `local-agent-db-service` в bundle:

```yaml
- insert:
    - id: local-agent-db-service
      name: '@local/dsh-agent-db'
      config:
        stateDirectory: /path/to/private/agent-db-state
        pgxHome: /path/to/dedicated/pgx
```

По умолчанию состояние находится в `~/.local/state/dsh-agent-db`, PGX_HOME —
в его подкаталоге `pgx`. Один каталог состояния должен обслуживать один Host-сервис.
Субагентам нужен пресет с тем же модулем инструментов. В новом диалоге проверьте
видимость `db_create` и `db_list`: установка пакета сама по себе не подключает tools к пресету.

## Инструменты

| Инструмент | Назначение |
|---|---|
| `db_create(label, ttl_seconds?)` | Создать базу и отдельную SQL-роль, получить id |
| `db_list()` | Список своих и явно разделённых баз, session_id вызывающего |
| `db_query(database_id, sql, parameters_json?)` | Выполнить один SQL statement с `$1`-параметрами |
| `db_insert(database_id, table, rows_json)` | Записать массив JSON-объектов в существующую таблицу |
| `db_extend(database_id, ttl_seconds)` | Владелец задаёт срок хранения от текущего времени |
| `db_export(database_id, sql, format, parameters_json?)` | Сохранить результат запроса в локальный JSON/CSV |
| `db_share(database_id, target_session_id, revoke?)` | Владелец выдаёт/отзывает SQL-доступ другой сессии |
| `db_drop(database_id)` | Владелец удаляет базу и её роль; экспорт сохраняется |

Пример поручения агенту:

> Создай временную базу для ключевых слов. Создай таблицу keywords с полями
> keyword, source_url и frequency. Запиши извлечённые слова через db_insert,
> сгруппируй частоты SQL-запросом, экспортируй результат в CSV и удали базу.
> Сообщи путь к файлу.

Пример аргументов инструментов после получения `database_id` из `db_create`:

```json
{"database_id":"<id из db_create>","sql":"CREATE TABLE keywords (keyword text NOT NULL, frequency integer NOT NULL)"}
```

```json
{"database_id":"<id из db_create>","table":"keywords","rows_json":"[{\"keyword\":\"навес\",\"frequency\":3},{\"keyword\":\"навес\",\"frequency\":4}]"}
```

```json
{"database_id":"<id из db_create>","sql":"SELECT keyword, SUM(frequency) AS frequency FROM keywords WHERE keyword = $1 GROUP BY keyword","parameters_json":"[\"навес\"]"}
```

Текст извлекает модель. PGX хранит структурированные записи и выполняет SQL.
Для совместной работы субагент сообщает свой `session_id`, владелец вызывает
`db_share`. Получатель может читать, изменять данные и экспортировать их;
удалять базу и управлять доступом может владелец.

## Устройство и ограничения

- `index.js` создаёт Host-сервис, `tools.js` регистрирует инструменты,
  `manager.js` управляет SQL-ролями, базами, реестром и очисткой через `pg`.
  Принадлежность определяется по `exec.agent.session.id`, а не аргументом модели.
  Каждая база имеет свою роль без административных прав. Реквизиты не возвращаются tools.
- Это разграничение инструментов доверенного локального Harness. Агент с полным
  shell-доступом от того же OS-пользователя может читать его файлы и настройки.
- TTL — скользящий срок от последнего обращения: по умолчанию 24 часа,
  диапазон 60 секунд–7 суток. Запрос продлевает срок до и после выполнения.
  Очистка каждые 30 секунд и при старте работает внутри Harness. Пока Harness
  выключен, этот сборщик не работает. Это TTL плагина, а не TTL CLI PGX.
- До 5 баз на владельца и 32 всего. Очередь до 32 операций; исполнение последовательное.
- Один SQL statement за вызов, 15 секунд, до 1000 строк / 1 MiB ответа.
  SQL до 64 KiB, параметры до 1 MiB / 10000 значений. Экспорт имеет тот же лимит ответа.
  Для больших объёмов используйте агрегацию и постраничную выборку.
- `db_insert`: 1–500 объектов с одинаковыми полями, до 50 столбцов.
  Имена таблиц ограничены простыми `table` или `schema.table`, значения параметризованы.
- SQL-соединение закрывается после каждого вызова. Транзакции между вызовами
  и сохранение `SET` не поддерживаются. Таймаут/лимит ответа не гарантирует отката
  уже выполненной записи; проверяйте результат перед повтором.
- Реестр с реквизитами имеет режим 0600, каталог состояния — 0700.
  Перед доступом/удалением сверяются имя и OID базы; неизвестные базы не очищаются.
- JSON/CSV сохраняются в `stateDirectory/exports` с режимом 0600, до 100 файлов
  на сессию. Удаление БД их не удаляет. CSV защищает ячейки от формул таблиц;
  JSON сохраняет исходные значения. Старые экспорты удаляйте отдельно.
- PGX beta не заменяет основную production-БД. Скорость клонирования зависит от
  файловой системы; адаптер не обещает показатели ZFS CoW на ext4.

## Проверка

```sh
npm run check
npm pack --dry-run
```

Перед первой публикацией пройдены 14 ручных инструментальных сценариев на настоящем
PGX: SQL с параметрами, изоляция сессий и ролей, share/revoke, owner-only операции,
экспорт, лимит ответа, отмена, продление и фактическое удаление по TTL.
Живой агент и его субагент в Harness на Gemini 3.8 Flash отдельно прошли цикл
создания, записи, выборки, экспорта и удаления; временные базы и роли удалены.
CI проверяет синтаксис и состав пакета. Он не запускает PGX и модели.
